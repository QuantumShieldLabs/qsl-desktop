Design notes (not UI).
  1. Entry points: the Contacts pane link is renamed “Invitations” and keeps the waiting count; a second entry, “Invitations”, sits in the Settings nav. Both open this page in the main panel. Creation stays on Contacts “+”.
  2. Row language is a sentence, not a status code: “Waiting for reply”, “Connected · not verified”, “Connected · verified”, “Expired”. Waiting rows can be revoked; expired rows are cleared. No row ever shows a code.
  3. Verification is a pop-up, never inline: “Verify” on any connected-unverified row opens the existing verify modal (mockup 13a). The page nudges once, at the top, with the count and direct links — it does not nag per row.
  4. One line per contact, nothing expands. The invitation code is shown ONCE, in the creation dialog, and dropped from memory when it closes; that dialog carries the guidance (“this is the only time you'll see it”, a close confirmation, and “if it's lost, revoke and create a new one”). This page never explains codes. Verification codes are separate and static; they belong to the verify pop-up.
  5. One name, everywhere (operator ruling): a renamed contact is renamed throughout; the original label is not kept. Rows show the contact’s current alias; waiting rows show the label typed at creation.
  6. Received depends on a record of redeemed codes existing in the store; if it does not yet, the group renders its explanation and the lane files the gap.
